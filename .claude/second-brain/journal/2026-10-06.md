# 2026-10-06

- [[launchheim]]'s check that Steam is running and logged in only worked on Linux. Windows read
  `ActiveProcess/ActiveUser` from the registry, the value Linux Steam already stopped writing to
  `registry.vdf`. `SteamClient` now reads the last state in `logs/connection_log.txt` on Windows too,
  in the Steam folder `SteamLibraryLocator` finds (registry `SteamPath`, then the default folder).
- A `steam` process whose start time can't be read (access denied, e.g. Steam run as administrator)
  used to count as not running; it now counts as running.
- Not yet tried on a real Windows machine: whether the Windows `connection_log.txt` has the same
  `[time] [Logged On, …]` lines as Linux. The format comes from the shared client code, and a
  `\r\n` line ending is covered by a test.
- Added the update reminder (sidebar line, dialog with download page and per-system commands, skip
  this version, never remind; Settings → About switches it back on) and prepared 0.5.2 with it and
  the Windows Steam fix. Checked against the real releases API with a build that claims 0.4.0: on
  CachyOS it offers `curl -LO …pkg.tar.zst` and `sudo pacman -U`. The dialog's four buttons didn't
  fit one row (RowLayout pushes the dialog wider), so they're two rows.
