# 2026-09-26

- Picked up [[launchheim]] from the previous session, which had built the app but not committed it.
  It builds, 69 Core tests pass, and the Library, Browse and Settings pages render (verified with the
  screenshot mode against the live Thunderstore index).
- Silenced the Qt 5.15 Material `ComboBox` binding-loop warning on the Browse page.
- Wrote `Applications/LaunchHeim/README.md` (the csproj already pointed to it) and the project note.
- Checked `install.sh` and `--register-desktop` with `HOME`/XDG pointed at scratch folders, so the
  real launcher and `nxm://` handler weren't touched. Found that `Encoding.UTF8` wrote a BOM into
  `launchheim.desktop`, which made `desktop-file-validate` reject it. Also dropped the second main
  category (`Utility`) so the app appears once in the menu, and made `--register-desktop` confirm the
  handler with `xdg-mime query` because `xdg-mime default` fails silently.
- Packaged [[launchheim]] for pacman (`launchheim-git` PKGBUILD), Debian/Ubuntu (.deb, self-contained
  .NET) and Fedora/RHEL (.rpm on `dotnet-runtime-10.0`). All of them use the system Qt 5.15
  ([[0005-launchheim-distro-packages-use-system-qt]]). They install cleanly and render in Arch, Debian 13,
  Ubuntu 24.04, Fedora 44 and AlmaLinux 9 and 10 containers. Found and neutralized a stale
  `/home/travis` RPATH in libQmlNet.so.
- Evaluated Windows: the QML UI can stay ([[0006-launchheim-windows-keeps-qml]]). Ported the Core
  (Doorstop via `winhttp.dll` plus command-line switches, registry Steam path, Windows folders) and
  added `packaging/windows/build.ps1` and a Windows workflow that builds a patched QmlNet.dll.
- The owner chose MIT for [[launchheim]]. Added `Applications/LaunchHeim/LICENSE` and installed it the
  way each package format expects. This cleared namcap's license error.
