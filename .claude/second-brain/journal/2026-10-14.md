# 2026-10-14

- LaunchHeim (branch `launchheim-steam-launch-options`): a command line (`play`, `steam`, `list`,
  `help`) and Steam's own Play button starting the last play through `launchheim steam %command%` in
  Valheim's launch options ([[0015-launchheim-steam-launch-options-wrap-steams-command]]).
- Steam's Linux launch config for Valheim is plain `valheim.x86_64` (an OpenGL entry adds
  `-force-glcore`); `start_Valheim.sh` in the owner's game folder is a leftover of their own.
- LaunchHeim (.NET) runs fine as a wrapper inside Steam's scout runtime (`steam-runtime/run.sh`) with
  the overlay preloaded; the overlay only prints "pid ... skipping destruction (fork without exec?)".
- Gotcha: the Bash tool's shell here is zsh, which doesn't word-split `$VAR` into a command; put
  multi-word env prefixes in a bash script or an array.
- Review follow-up: Copy didn't work on Windows. Cause: no `[STAThread]` on `Program.Main`, so Qt's
  OLE clipboard never initialised; proved by a new clipboard check in the Windows smoke test failing
  before the fix (see Gotchas in [[launchheim]]). All Copy buttons go through `Clipboard.qml` now.
- Text in every text field sat 4 px high (Material's asymmetric padding); fixed in `LhTextField` and
  `SearchField`.
