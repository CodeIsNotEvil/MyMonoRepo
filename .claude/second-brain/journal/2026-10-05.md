# 2026-10-05

- Built LaunchHeim Companion, the Android app ([[launchheim]], branch `launchheim-android-companion`).
  The owner picked Kotlin + Compose over a .NET app reusing Core, and the LocalSend protocol in both
  apps over relying on the LocalSend app ([[0011-launchheim-companion-syncs-packs-over-localsend]]).
- Core got `LocalSend/` (node, HTTP server), `PackService.Read/Compare/ApplyAsync`, `instanceId` in
  `launchheim.json` and `ServerListExport`. The desktop got Send to phone, an accept dialog, an
  update-instance dialog and Settings → Phone sync (off by default).
- Installed the Android SDK under `~/.local/share/android-sdk` with the owner's go-ahead.
- A C#↔Kotlin run over localhost found that a phone-made pack had an empty `exportedAt`, which the
  desktop can't parse as a `DateTimeOffset`; the phone now always stamps it.
- Checked on an emulator: receiving from the desktop code through `adb forward`, the Thunderstore list
  (12.5k packages), mod details with README, updates, and A2S "3/10 online" against a fake server on
  the host. Not yet tried with a real phone on Wi-Fi.
- Follow-up the same day: the phone adds Nexus (anonymous GraphQL) and CurseForge (own API key)
  mods by file id, with CurseForge's dependencies; "Duplicate as a new list" for turning a list into a
  new instance. Applying a pack keeps dependencies it doesn't list while needed.
- The APK is now part of the `launchheim-v*` release and the download page. A tag fails without the
  `LAUNCHHEIM_ANDROID_KEYSTORE*` secrets on purpose. Google's developer verification covers sideloaded
  APKs (enforced in four countries since 2026-09-30, globally in 2027); options are in
  `android/README.md` "Releases".
- Released 0.5.0 after two Windows jobs were cancelled by a GitHub runner incident ("job was not
  acquired by Runner of type hosted"); re-running the failed jobs after the incident cleared worked.
  The installed 0.5.0 then crashed on Send to phone with an empty library (Qml.Net's empty string is
  null), fixed in PR #26.
