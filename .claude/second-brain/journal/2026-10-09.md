# 2026-10-09

- First try of [[launchheim]] Companion between the owner's Redmi Note 13 5G and the CachyOS desktop on
  the same LAN: every send from the phone failed with "connection refused", and the desktop showed up
  on the phone only for a few seconds after switching phone sync on. Cause: ufw, which CachyOS turns
  on with `DEFAULT_INPUT_POLICY="DROP"` and no rule for 53317. The kernel log had
  `[UFW BLOCK] ... SRC=<phone> DST=224.0.0.167 PROTO=UDP DPT=53317`. Allowing UDP 53317 and TCP
  53317:53327 from the LAN fixed it. Not the code: desktop → phone sends had worked all along.
- Gotcha: a firewall that drops incoming traffic shows up as a PC that appears briefly. LaunchHeim's own
  announcements go out, but the phone's next search clears its list and needs an answer the firewall
  drops. ufw's log is limited to 3 lines a minute, so most blocked packets never show.
- Unexplained: a dropped SYN should be a timeout on Android, not "connection refused". The owner's
  wording or HyperOS may explain it; not looked at further once the rule fixed it.
- Gotcha: the desktop is on the LAN twice (`eno1` .26 and a USB adapter .49, same /24). It announces on
  both, so the phone keeps whichever address came last. Harmless.
- Phone-made lists sent to the PC were imported again on every send (`test`, `test-2`, `test-3` in the
  log): their packs had no `instanceId`, and the phone never learns the PC's folder-name id. Fixed with
  a link id that either side can create: the phone stamps its own id, LaunchHeim keeps it as
  `Instance.LinkId` and exports it instead of `Id` ([[0011-launchheim-companion-syncs-packs-over-localsend]]).
- Checked with probes in a throwaway copy of the built QML that Qml.Net hands .NET's `""` to QML as
  `""` (not null) and keeps U+001F in strings both ways. So the send dialog's preselection worked; the
  two logged sends of "the server list" only were what was ticked.
- The owner asked for one thing per send button: the instance page sends that instance (phone button
  next to the console), the Play page's server list sends the servers. The all-in-one dialog
  (Library and Settings buttons) is gone.
- Packages now ship a ufw profile (`sudo ufw allow LaunchHeim`) and a firewalld service; Settings →
  Phone sync shows the ufw command when ufw would drop phones, and on Windows adds the firewall rule
  (elevated PowerShell). An all-users Windows setup adds it itself with netsh. Branch
  `launchheim-phone-sync-firewall`.
