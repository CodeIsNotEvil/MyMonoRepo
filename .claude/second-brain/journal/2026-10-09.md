# 2026-10-09

- First try of [[launchheim]] Companion between the owner's Redmi Note 13 5G and the CachyOS desktop on
  the same LAN: every send from the phone failed with "connection refused", and the desktop showed up
  on the phone only for a few seconds after switching phone sync on. Cause: ufw, which CachyOS turns
  on with `DEFAULT_INPUT_POLICY="DROP"` and no rule for 53317. The kernel log had
  `[UFW BLOCK] ... SRC=<phone> DST=224.0.0.167 PROTO=UDP DPT=53317`. Allowing UDP 53317 and TCP
  53317:53327 from the LAN fixed it. Not the code: desktop → phone sends had worked all along.
- Gotcha: a firewall that drops incoming traffic shows up as a PC that appears briefly. LaunchHeim's own
  announcements go out, but the phone's next search clears its list and needs an answer the firewall
  drops. ufw's log is limited to 3 lines a minute, so most blocked packets never show.
- Unexplained: a dropped SYN should be a timeout on Android, not "connection refused". The owner's
  wording or HyperOS may explain it; not looked at further once the rule fixed it.
- Gotcha: the desktop is on the LAN twice (`eno1` .26 and a USB adapter .49, same /24). It announces on
  both, so the phone keeps whichever address came last. Harmless.
- Phone-made lists sent to the PC were imported again on every send (`test`, `test-2`, `test-3` in the
  log): their packs had no `instanceId`, and the phone never learns the PC's folder-name id. Fixed with
  a link id that either side can create: the phone stamps its own id, LaunchHeim keeps it as
  `Instance.LinkId` and exports it instead of `Id` ([[0011-launchheim-companion-syncs-packs-over-localsend]]).
- Checked with probes in a throwaway copy of the built QML that Qml.Net hands .NET's `""` to QML as
  `""` (not null) and keeps U+001F in strings both ways. So the send dialog's preselection worked; the
  two logged sends of "the server list" only were what was ticked.
- The owner asked for one thing per send button: the instance page sends that instance (phone button
  next to the console), the Play page's server list sends the servers. The all-in-one dialog
  (Library and Settings buttons) is gone.
- Packages now ship a ufw profile (`sudo ufw allow LaunchHeim`) and a firewalld service; Settings →
  Phone sync shows the ufw command when ufw would drop phones, and on Windows adds the firewall rule
  (elevated PowerShell). An all-users Windows setup adds it itself with netsh. Branch
  `launchheim-phone-sync-firewall`.
- PR #34 merged. The owner then asked to send an instance's mod list to a friend over Steam or Discord,
  with a copy-the-file button if an integration is too much. No integration (neither has an API to
  post a file as the user): a Share dialog on the instance page writes the pack and offers it as a
  drag tile, Copy file (native `launchheim_copy_files`) and Show in folder. Branch
  `launchheim-copy-modpack-file`.
- Gotcha: Discord's Linux client has been reported (2019-era feedback, not checked since) to paste only
  `image/png` and ignore files copied in a file manager; dropping a file works. So the dialog leads
  with the drag tile.
- The owner tested sharing: dragging and Copy file work into Discord and the file manager "like a
  charm" (so the old Discord paste reports no longer hold). Steam's chat only takes images and videos,
  so the dialog no longer mentions Steam, and names no app at all, since any place that takes a file
  works.
- Checked the clipboard on the real Plasma Wayland session with a small Qt reader built in the
  scratchpad (no wl-paste/xclip/Tk here): through XWayland, where Discord runs, it lists
  `text/uri-list` and `x-special/gnome-copied-files` with the pack's file:// URL. The reader on native
  Wayland saw nothing, likely because its window had no focus; not looked into.
- The extra share button pushed the instance page's header to 1088 px against about 1011 available at
  the old 1320-wide default, so the right edge (the ⋮ menu, Check for updates) was cut off. Measured
  with `implicitWidth` probes in a throwaway QML copy. The rigid part was the stats row (434 px). Fix:
  the title column shrinks to at least 200 with the stats in a Flow, the filter field narrows to 160,
  default 1400×820 (clamped to the screen at start), minimum 1180, which still fits a Steam Deck's 1280.
- Gotcha: QML's offscreen platform reports an 800×600 screen, so start-up code that fits the window to
  `Screen.desktopAvailableWidth` has to leave the screenshot mode alone.

- PR #35 merged. The owner wanted less text at first sight. First the sentence under each page title
  (`PageHeader`) faded in on hover; after trying it the owner had them removed entirely, as what each
  page is for is obvious. `PageHeader` has no subtitle any more. The Screenshots page's empty state
  still explains F12, and Open folder replaces the folder path its sentence showed.
- CurseForge never worked: the owner's key is valid (`/v1/games` answers 200 with 38 games), but Valheim
  isn't among them, and `mods/search?gameId=68940` (the id I believe is Valheim's; unconfirmed) answers
  403 "API Key missing or invalid". So CurseForge offers no Valheim mods to third-party keys. LaunchHeim
  said "does not list Valheim for this API key", which read like a bad key; it now says the key is
  fine and CurseForge doesn't offer Valheim. Removing the CurseForge source is the owner's call.
- Nexus: the owner found that the key to paste is the one Nexus lists for Vortex on the API keys page.
  The Settings text says so now, and is shorter.
- The owner keeps the CurseForge source for if CurseForge ever opens Valheim to the API (they're asking
  CurseForge in a ticket). Settings now says to download Valheim mods on CurseForge's site (linked to its
  Valheim search) and drop the file onto an open instance; the instance page installs dropped mod
  files (`DropArea`, `text/uri-list`, local files only) through Install from file.
- Gotcha: in a QML rich-text `href`, write `&` as `&amp;`; `linkAt` (and so `onLinkActivated`) hands
  over the decoded URL (checked with a probe).
