# 2026-10-08

- Created a self-signed Authenticode certificate for [[launchheim]]'s Windows build
  ([[0012-launchheim-windows-self-signed-code-signing]]) and backed up the `.pfx` and `.cer` next to the
  APK key in `/mnt/BackupHDD/KeyBackups/LaunchHeim/` (README.txt there has the thumbprint and restore
  steps). The password lives only in the password manager and the GitHub secret.
- Gotcha: `openssl pkcs12 -passin file:X -passout file:X` with the same file reads line 1 for input and
  line 2 for output, so a one-line password file fails ("Error reading password from BIO"). Use
  `env:VAR` for both.
- The owner set `LAUNCHHEIM_WINDOWS_SIGNING_PFX` / `_PASSWORD`. The Windows workflow then signed all five
  files with the expected thumbprint (DigiCert time stamp) and the smoke test passed on the signed
  exe. A run that started before the secrets existed skips signing: secrets are read at job start.
  CHANGELOG has a 0.5.3 section for it; the version bump follows after the merge.
- PR #29 merged. The owner then held 0.5.3 back for a Windows installer: Inno Setup setup with optional
  shortcuts, and **Update now** in the update dialog runs the new setup
  ([[0013-launchheim-windows-setup-with-inno-setup]]). Same PR as the version bump (#30).
- Gotcha: a QML `Dialog` whose content has two items (the update dialog's hidden clipboard `TextEdit`
  next to its `ColumnLayout`) gets no implicit content size, so its background only covered the
  title. Keep a single content item; an invisible item inside a layout takes no space.
- Gotcha: the screenshot timer grabs `root`, which leaves out popups. Grabbing
  `window.contentItem.parent` includes them (used only temporarily to check the dialog).
- After playing 0.5.3 the owner found Steam's overlay missing (no Shift+Tab, no F12). Cause: Steam
  only injects it into games it starts. Fixed per OS ([[0014-launchheim-steam-overlay]]) and added a
  Screenshots page, on branch `launchheim-steam-overlay-screenshots`, changelog 0.5.4.
- Gotcha: Steam's own `logs/console_log.txt` shows `AppID 892970 adding PID ... as a tracked process`
  for a directly started game too, so a tracked process doesn't mean the overlay is in it.
- PR #31 merged. The owner then saw a white title bar on Windows in dark mode. Windows draws it and
  keeps it light unless the window sets `DWMWA_USE_IMMERSIVE_DARK_MODE` (20, 19 before 20H1); Qt 5.15
  only does that with `-platform windows:darkmode=1`, following Windows rather than LaunchHeim's theme.
  `native/app_icon.cpp` now sets it from an application event filter on `PlatformSurface`
  `SurfaceCreated`, so every window (the console too) gets it before its first frame. CI checks it in
  dark mode with `DwmGetWindowAttribute` and a screen capture.
